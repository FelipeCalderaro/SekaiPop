# Changelog

## Unreleased
- Sounds: the error sound reaches kitty. Kitty hands its bell to the compositor (the Wayland system-bell protocol), and Hyprland played it from the default freedesktop theme, never from the `__custom` theme the setting wrote, so kitty kept the stock bell while Try it sounded right. The setting now also puts the chosen sound (or Off) in a user-level freedesktop theme holding only `bell-window-system`, which libcanberra reads ahead of the system's: Hyprland's bell, and so kitty's, foot's and any other app's that rings through it, follows the setting, live. Try it plays the bell the same way (docs/SOUNDS.md).
- Calendar card: **Google calendars**, the easy way, with no API key, OAuth client or sign-in. Paste a calendar's *Secret address in iCal format* (Google Calendar > the calendar's Settings > Integrate calendar) in Settings > Desktop > Google calendars, one per calendar, from any number of accounts (any .ics or webcal:// link works too). Its events show on the card beside yours, each calendar in its own colour, read-only, fetched at start and every 15 minutes (Sync now, `ipc call calendarcard sync`), repeating events expanded and moved to your time zone. The links stay in a private file (`~/.config/sekaipop/calendars.json`), never in settings, presets or logs (docs/CALENDAR-SYNC.md).
- Terminal prompt: a compact **pill** style, now the default: one line, each plate a rounded pill in the same colours (folder, git branch with ● ↑ ↓, command time, a red one after a failure) with the arrow right after them, instead of four rows of outline and shadow, which came out especially tall with Kitty's taller lines. The old look is `sticker` (`~/.config/sekaipop/prompt-style`, docs/TERMINAL.md). With ble.sh, its own exit-status and elapsed-time notes are turned off: the pills already say both.
- Settings: the sideways phone stays sharp after it has turned. Once the turn landed, the phone's picture was shrunk to the screen by a fraction (1.6x, say: the big landscape phone rarely fits twice its size in the memory budget) through mipmaps, which blends in a half-size copy, so it went soft the moment the rotation finished. At rest it is now drawn at a whole 2x or 1x, which the mipmaps shrink cleanly.
- Keybinds: **Super + Shift + I** turns the flat (2D) phone on and off, the same switch as Settings > Quick > Phone. `ipc call options toggle <setting>` flips any on/off setting.
- Install: reloading Hyprland at the end works in every mode and says what happened. `--reload ask|yes|no` (default ask): ask offers the reload after a full or a merge install (merge used to get none, though it adds a session file), yes reloads Hyprland and restarts the shell without asking in every mode, `--hypr skip` included, and no leaves both alone. The installer now reports whether Hyprland confirmed the reload and lists any config errors it reported; before, `hyprctl reload` ran with its output thrown away, so a reload that failed looked like one that worked.
- Keybinds: the cheatsheet (Super + /), the split ratio keys (Super + ; and '), the welcome tour and the bracket keys are bound by key position (`code:N`) instead of by character. Hyprland reads character binds through the FIRST layout in kb_layout, whichever one you type in, so with a Brazilian ABNT2 layout first, Super + / was Super + ; and resized the window instead, even while typing English. A position bind is the same key in every layout; Super + Slash stays as an extra for ABNT2's own / key. The cheatsheet and the keybind editor show these keys by their character.
- Keyboard: **Primary layout** in Settings > Hyprland > Keyboard layouts: pick which of your layouts Hyprland starts on and reads shortcuts through (it moves to the front of kb_layout, variants kept).
- Keyboard: more layouts and variants in Settings > Hyprland > Keyboard layouts (US International, Latin American Spanish, Canadian French, the Nordic and Central European layouts, Greek, Hebrew, Hindi, Thai, Vietnamese, Dvorak, Colemak and more), and a layout can carry a variant (`us:intl`, `de(nodeadkeys)`), kept in `kb_variant` by position instead of being wiped whenever the list changed. A new **Keyboard model** choice sets `kb_model` (Brazilian ABNT2 for its extra /? key, US 104, Japanese 106). The bar and lockscreen say EN for English layouts and the layout's code otherwise (BR, DE, UA), where the keymap's name gave PO, GE or UK. Fixed: an unset Hyprland option read as `[[EMPTY]]`, which was written back into `kb_options` ahead of the switch key.
- Install: the Spotify theme's Spicetify install works again. The AUR `spicetify-cli` build runs `node`, but its package lists only go and pnpm, and Arch's pnpm no longer brings nodejs, so the build stopped half way and `spicetify` never appeared. `app-setup.sh spotify-deps` (what install.sh and install-deps.sh run) installs nodejs first, as a dependency, and falls back to the prebuilt `spicetify-bin` if the build still fails.
- Terminal prompt: the git plate shows uncommitted changes (●) and how far the branch is ahead of / behind its upstream (↑2 ↓1), from one `git status` call. In bash the plates are now part of PS1 (Ctrl+L redraws them; folder and branch names are escaped so a name like `$(...)` never runs), and when ble.sh is installed the prompt loads it for suggestions from your history as you type. `blesh-git` (AUR) is in the dependencies and `check-deps.sh` (docs/TERMINAL.md).
- Install: the terminal look is part of the default install. `install.sh --terminal auto|yes|no` (default auto: everything on for a first install; a reinstall refreshes only the parts already on): the Kitty look, neofetch with your banner, and the Terminal prompt switch. neofetch is in the dependencies now (AUR), and `check-deps.sh` lists it and Maple Mono NF (docs/TERMINAL.md).
- Updates: About / Update checks the `origin` remote (this fork, FelipeCalderaro/SekaiPop), not whatever the branch tracks. A git checkout fetches and compares `origin/<branch>` and `Update now` pulls from origin; an installed copy asks the repo install.sh recorded (the checkout's origin), and the fallback and `get.sh` now point at the fork. An install made from commits not pushed yet no longer shows as an update waiting: install.sh records the checkout (`src=` in `.source`) and the check sees the remote is behind it.
- Quick Panel: **Shut down** on the phone's Power rail asks first. The first click (or Enter) turns the pill red and says "Click again to shut down"; a second click within about 3 seconds powers off, otherwise it lapses, the same click-twice as SAVE OVER on a desktop preset. It now runs `poweroff` straight away; `systemctl poweroff` could start a scheduled shutdown instead.
- Terminal: a neofetch look with your Quick Panel **banner** or **profile picture** beside the system info, as a sticker card (rounded, outlined in the theme's accent, hard shadow in its second accent), Nerd Font icons and the theme's colours. Choose the picture in Settings > General > Quick Panel > Neofetch picture. Turn it on with `sh sekaipop/scripts/theming/neofetch-setup.sh enable` (your config is kept as `config.conf.sekaipop-bak`; `revert` puts it back) (docs/TERMINAL.md).
- Terminal: a Kitty look (`sh sekaipop/scripts/theming/terminal-look.sh enable [font]`): a Nerd Font with character (Maple Mono NF if installed, else Victor Mono, Lilex, Geist Mono, then JetBrains Mono), taller lines, padding, a beam cursor with a short trail and rounded tabs, in `sekaipop-look.conf` included at the top of kitty.conf so your own settings still win. And the App colours **Terminal prompt** (the sticker plates) works in bash now too, not only fish: one managed block at the end of ~/.bashrc (docs/TERMINAL.md).
- Settings: choose the error sound, the bell a terminal plays when Backspace has nothing to delete (Settings > General > Sounds): your sound theme's own, Soft, Chime, Pop, Ding, a file of yours, or Off, with Try it. kitty and GTK apps follow (through the XDG `__custom` sound theme, which inherits yours; Default takes it out and gives GTK its theme back; a `__custom` theme of your own is left alone). Idle & sleep's three times are also on the Quick page now, and General's tile says it holds them (docs/SOUNDS.md).
- Login screen: an SDDM theme with the lockscreen's look (the gacha style): your lock wallpaper, the slate panel with the user who logs in on the mint tab, the big outlined clock, the session as a capsule, power keys, and the Password and Log in pills (dots in the card colours, a pink bubble when the password is wrong). It follows the shell's theme, lock wallpaper, avatar and 12/24 h. `install.sh` asks (default no; `--sddm yes|no`); it installs the theme with sudo and selects it in /etc/sddm.conf.d/zz-sekaipop.conf after writing down the theme you had. `./install.sh --restore-sddm` takes it out and gives SDDM that theme back. Try it without logging out: `sh sekaipop/scripts/theming/sddm-theme.sh preview` (docs/SDDM.md).
- Wallpapers: choose which monitor a wallpaper goes on. With more than one monitor, the wallpaper viewer has a **Set on** row above Set as Desktop / Lockscreen: All monitors, or one of them, each with a thumbnail of what it shows now ("here" marks the one the board is on). Setting one monitor turns on One wallpaper per monitor by itself when it was off, and the other monitors keep exactly what they show. Shift+click still means every monitor. A desktop preset keeps each monitor's wallpaper and lockscreen wallpaper, as before (docs/WALLPAPER-PER-MONITOR.md).
- Quick Panel: an **Idle & Sleep** tile, for the phone. Add it from the panel's edit mode; it says what happens first ("Lock 5 min", "Never") and a click opens a card with the lock, screen-off and sleep times and Suspend / Hibernate, the same settings as Settings > General > Idle & sleep. Its - / + keys go through round values (Never, 1 ... 45 min, 1 h ...). It says in amber when the times clash (it would sleep before the screen turns off) or when hypridle isn't using them yet (docs/IDLE.md).
- Plugins: seven new desktop widgets, bundled and installed with the rest (each off until you add it from Edit Desktop's shelf; settings in Settings > Desktop > Plugins). **Market Ticker**: a live candlestick (or line) chart of a crypto pair with its price, 24 h change, candle intervals and a watchlist strip, from Binance's public market data (no account, no key; live over a WebSocket); rising candles are filled and falling ones hollow, so it reads without colour. **Ping Board**: up to 6 hosts with bar graphs of the last 30 pings and how each is doing in words, and a speed test on a key. **GIF Frame**: a looping GIF or picture in a Polaroid, taped or block frame; point it at a folder for a different one every so often. **Cover Wall**: what's playing as a spinning record over the albums you played lately, from any player. **Countdowns**: stickers counting down to your dates, yearly ones too. **Rain Radar**: the radar around you as a loop on a map (RainViewer). **Desk Pet**: Mochi, who wanders a strip of your desktop, dances to music, naps when you're idle and hops when you click it. All of them run only while on screen and say problems in words (docs/WIDGET-PLUGINS.md). For plugin authors: the block, keycap, sticker and tag components are in `examples/plugin-kit/`, and `sekaipop/tests/plugin-widgets-test/run.sh` unit-tests a plugin and draws its widget offscreen in each mode, without a running shell.
- Install: `install.sh` and `install-deps.sh` set up the Spotify and Discord themes, with your yes. For each app you have, they say what it takes and ask (default no; `--yes` alone never says yes for these; `--spotify yes|no` and `--discord yes|no` answer in advance). Spotify: Spicetify from the AUR, Spotify's folder made writable (sudo chmod) and the App colours switch turned on. Discord: Discord can't load themes, so it DOWNLOADS the official Vencord installer (github.com/Vencord/Installer), patches Discord with it (no sudo for Discord's own self-updating client in ~/.config/discord), and puts the theme in Vencord's themes folder, ticked, keeping your other Vencord settings. Vesktop needs no download. A finished setup is left alone. `check-deps.sh` lists both. Also fixed: the Spotify switch in Settings could not turn on (its setting had no default, so it was dropped) (docs/SPOTIFY-DISCORD-THEME.md).
- App colours: Spotify follows the theme. A new **Spotify** switch in Settings > Desktop > App colours puts a Spicetify theme on it: the theme's colours, panels drawn as the shell's blocks (outline and a hard shadow straight down), a keycap play button that drops and springs back, menus as blocks, and text kept readable (4.5:1) in every theme and in Light, Dark and Darker. Changing the theme, the mode or the wallpaper rewrites it. Spotify is never restarted, so the music doesn't stop: press Ctrl+Shift+R in Spotify (or start it again) to see new colours. Needs Spicetify, and Spotify's folder writable once (`sudo chmod a+wr /opt/spotify && sudo chmod a+wr /opt/spotify/Apps -R` for the Arch package); Settings says so if it isn't. Revert gives Spicetify back the theme you had. `ipc call apptheme apply spotify` (docs/SPOTIFY-DISCORD-THEME.md).
- Discord: the theme is the shell's block look by default. It used to be CapnKitten's Material Discord; now it is the sekaipop look, with every floating card, the chat bar, menus and popouts given the theme's outline and a hard shadow straight down (menus had a soft blurred shadow before). `look=material` in `~/.config/sekaipop/discord-options` brings Material back. Discord still needs Vencord (or Vesktop) and the theme ticked once in Vencord > Themes (docs/SPOTIFY-DISCORD-THEME.md).
- Keybinds: SUPER + ALT + arrow moves the workspace you are on, with all its windows, to the monitor in that direction, and you go with it. The direction follows the monitor layout (Settings > Hyprland > Displays), so a portrait monitor on the left is to the left whatever its rotation or name. At the edge it goes round: Left on the leftmost monitor goes to the rightmost, Up on the top one to the bottom one; with two monitors side by side, Left and Right both send it to the other one. With one monitor, or Up / Down when the monitors are side by side, nothing happens. An open scratchpad stays where it is; the workspace under it moves. The cheat sheet lists the four keys as one row under Workspaces. To change or drop one, add `hl.unbind("SUPER + ALT + Left")` (and your own bind) to `~/.config/hypr/custom/keybinds.lua`. Update now doesn't touch the Hyprland config, so on an existing install run install.sh again (it keeps your own edits to `keybinds.lua`).
- Edit Desktop: the shelf fits a narrow (portrait) monitor. Its three side columns (the title and how-to, the 3 x 2 tabs, Lock all / Done) left a 1080-wide monitor about 280 px for the tab itself, so every tab was squeezed. Under 1400 design px wide the shelf now stacks instead: one row on top with the title, the six tabs and Lock all / Done, the how-to in a row under it (same order), and the tab's content across the whole card (about 1000 px on a 1080 monitor). Under about 1040 px the tabs take a row of their own. The keys keep their size and look; the shelf is taller and the desktop card above leaves room for it (`EditMode.compactShelf`). The BAR tab's RESET / CLEAR ALL keys, shown as icons when tucked, say what they do on hover and have bigger click targets.
- Install: reinstalling keeps your own Hyprland edits. Before, `install.sh` rebuilt `~/.config/hypr` from the shipped files and kept only monitors.lua, workspaces.lua, sekaipop_overrides.lua and custom/, so a change made in a shipped file (mouse settings in hyprland/general.lua, say) was replaced; it was only in the backup. Now each shipped file you changed is compared with what was shipped last time: your edit is kept, merged with the update when both changed it (diff3), or, if the two clash, your file is kept and the new one is put beside it as `<file>.sekaipop-new`. Files you added are kept. Whitespace-only differences (an editor reformatting a file) don't count. The installer records what it shipped in `~/.config/hypr/.sekaipop-shipped/` (the first time, it asks git for the files of the commit installed before).
- Bar: a wrapped bar whose zones each have a row to themselves centres them, so a portrait monitor's three rows read as one column instead of a staircase (left zone at the left edge, centre in the middle, right zone at the right edge). Rows two zones share keep their edges.
- Edit Desktop: the BAR tab works on a narrow (portrait) monitor. Its lanes were squeezed below the width their keycaps need, so they overlapped, keycaps spilled out under the shelf and the OFF lane was cut off. Lanes now keep their size and scroll sideways (wheel, or hold a keycap near either end while dragging), and RESET / CLEAR ALL shrink to their icons beside the STYLE heading instead of covering a lane's title.
- Bar: each monitor's bar can be set on its own in Settings > Bar > This monitor: hidden on that monitor only, on its own edge, and what happens when it doesn't fit. **Wrap** (the default) makes a flat bar too narrow for its modules, such as one on a portrait monitor, grow a second or third row: the left and right zones on the first, the centre zone under them. Before, the three zones slid over each other and the clock and date ended up under the utility keys. The window and its reserved space grow with it, and the popups, OSD, notifications and dock keep clear of the taller bar. **Overlap** keeps one row. `ipc call barposition hidescreen | setscreen | wrapscreen | getscreen <output> ...` (docs/BAR-PER-MONITOR.md).
- Docs: docs/DESIGN-SYSTEM.md describes the shell's design language: palettes and every derived colour per mode, type, icons, sizes, the block's construction, buttons and their states, motion and transition timings, the components and the bar, with recipes for shell code and plugins.
- Plugins: an AniList bar plugin in `plugins/anilist/`: the next episode's countdown (or your progress, list count or notifications) in the bar, and a card with your current list, covers, progress bars and +1 (signed in). It is connected and configured from its own card: type a username for a public list, or sign in with AniList (the card walks you through the one-time API client, then the token comes back by itself through a listener on localhost and is kept as the plugin's secret, mode 600); a Settings page on the card holds every option. No file to edit (plugins/anilist/README.md).
- Install: `install.sh` installs the plugins bundled in `plugins/` into `~/.config/sekaipop/plugins/` along with the rest, as copies (`--plugins link` links them to your checkout, `--plugins skip` leaves the folder alone). A plugin folder it replaces is moved to `~/.config/sekaipop/plugins.sekaipop-backup-<time>/` first; one you edited is kept there, plugins you added yourself and ones installed from Settings > Get plugins are never touched, and a running shell reads its plugins again. Bar entries stay off until you turn them on.
- Apps: while typing, Down takes the arrow keys into the grid on the first match, and then Left / Right move between the matches instead of the caret in the search box. Enter still opens the first match without any arrow key, and typing another letter gives Left / Right back to the caret. Before, Left / Right always moved the caret while something was typed, and the first Down jumped a whole row past the first match (docs/LAUNCHER-KEY-CURSOR.md).
- Apps: the app Enter would open is picked out by a mint plate behind its tile, the same look as a picked row above the grid, and the plate slides from tile to tile with the arrow keys. It also shows while typing, on the first match, so you can see what Enter opens before pressing an arrow key. The pick used to show only as the icon growing a little, like a mouse hover, which was hard to follow over a wallpaper (docs/LAUNCHER-KEY-CURSOR.md).
- Clipboard: pin an entry to keep it. On the Clipboard card (`clip ` on the Apps screen), pick an entry and press the pin key beside Delete, or Ctrl+P. Pinned entries sit at the top with a pin on them and outlive the history: cliphist's size limit, Clear history and deleting the entry they came from. Copy puts one back as it was (a picture with its own type); the pin key again, or Delete, lets it go. Pins are copies kept in `~/.local/state/sekaipop/clip-pins/` (docs/CLIPBOARD-PINS.md).
- Displays: a screen turned off in Settings > Hyprland > Displays can be turned back on. Hyprland kept the screen off when the rule turning it on didn't say so outright, so it stayed dark until the next login, and the 15-second "keep these?" countdown couldn't bring it back either. The rule now says `disabled = false` (issue #109; docs/DISPLAYS.md).
- Presets: a desktop preset keeps the phone's own picture (Settings > General > Quick Panel > Phone wallpaper > A picture), as it keeps the avatar and banner. Saving a preset copies the picture and its framing in beside it, and wearing the preset puts it back, even after you have picked another. A preset saved without one, or before this, leaves your phone picture as it is (issue #147; docs/PHONE-WALLPAPER.md).
- Recording: a screen recording no longer fails silently on a laptop whose NVIDIA driver is too old for NVENC. Having an NVIDIA card was taken to mean NVENC works, but `/dev/nvidiactl` only says the driver is loaded; with the legacy 580xx driver and a newer ffmpeg, `wf-recorder` quit at once ("Driver does not support the required nvenc API version"), nothing was saved and nothing was shown. `region-action.sh encoder` now tries a one-frame encode first and picks NVENC, else VAAPI on the other GPU (the Intel / AMD iGPU), else software; the bar's record key and the region picker share it. If `wf-recorder` still stops without saving a file, a "Recording failed" notification says so.
- Apps: the shell no longer freezes for a moment when a terminal opens or a video player opens a file. Quickshell re-reads the installed apps whenever a file changes in your home folder, and the Apps list was rebuilt once for every app it touched; with many apps, or apps installed in two places (a flatpak, an override in ~/.local/share/applications), that held the shell at full CPU. It is now rebuilt once, and only when an app was really added, removed or changed (issue #128; docs/APP-LIST-RESCANS.md).
- Dock: Smart hide works from the start. Started with a window already in the dock's way (a maximized one), the dock could stay over it, and it stopped following windows until Smart hide was turned off and on (or the dock pinned and unpinned). At startup the dock was built twice on a monitor, and the one going away switched off the window watching for the other (issue #116; docs/DOCK-SMART-HIDE.md).
- Quick Panel: **Peek first** (Settings > General > Quick Panel, off by default). With it on, the hot edge at the bottom centre of the screen raises only the tip of the phone, its clock and date; click the tip to bring the whole phone up, or move the mouse away and it drops again. A pointer that strays to the bottom of the screen no longer throws the phone up. The keybind and the bell still open it at once. `ipc call options set panel.hotPeek true` (docs/HOT-EDGE-PEEK.md).
- Lockscreen: the keyboard layout you are typing in (EN, RU, ...) is shown as a small tag on the corner of the password plate, in both lockscreen styles, so a password does not fail because the wrong layout was active. Click it for a list of your layouts above it, and pick one. It shows only when more than one layout is configured (Settings > Hyprland > Keyboard), like the bar's layout pill; both read one `KeyboardLayoutService` now, so they always agree (issue #110).
- Plugins: get them and keep them up to date from Settings. About / Update > Get plugins lists the reviewed plugins (plugins.json, read by a person before a plugin goes on it), searched by name, word or tag, and installs one with a key, showing the clone's progress and then the next step (turn its bar entry on, place its widget, its settings); From a URL reads any other plugin repository first and installs it only on Install it anyway. About / Update > Plugins says which have updates and shows the commits each brings, updates one or all, goes back to the commit before the last update, pins one where it is, and removes one (keeping its saved settings unless you say). Plugins linked to a folder of your own, or copied in by hand, are never touched. A notification says when plugins have updates, under the shell's own update rules (Tell me about updates, Look every); Desktop > Plugins' rows say where each came from. Everything is in ~/.config/sekaipop/plugins-lock.json, so `ipc call plugins restore` puts them all back on a new machine. `ipc call plugins install | check | update | goback | pin | remove | restore | open` (docs/PLUGIN-INSTALL.md).
- App fonts: pick the font of your GTK, Qt and KDE apps and their monospace font, and the sizes, in Settings > Desktop > App fonts (type part of a name, pick it from the matches). Open apps change at once, and a font picked here is put back at every start if something else changed it. A font set by hand often seemed to reset because each kind of app reads it from a different place: with SekaiPop's `QT_QPA_PLATFORMTHEME=kde`, Qt apps read `~/.config/kdeglobals` and never qt6ct's fonts, and GTK on Wayland reads GNOME's `font-name` over `settings.ini`. The section writes all of them (docs/APP-FONTS.md has the table). `ipc call fonts ui "Noto Sans" 10`, `ipc call fonts status` (issue #98).
- Plugins: a plugin can put an entry in the bar, with a card that opens under it, as well as (or instead of) a desktop widget. The shell draws the entry's pill in every bar style and on every edge, holds it pressed while its card is open, and opens the card like the built-in popups (one at a time, a click away or Esc closes it); the plugin draws only what is inside. The entry is one more module: Settings > Bar > Modules lists it, marked as a plugin with a key to its settings, and Edit Desktop's BAR tab moves it. It is off until you turn it on there. An optional `Service.qml` fetches once for the widget, the entry on every monitor and the card. `ipc call plugins bar <id> on | off | toggle`, `ipc call plugins popup <id>` (for a keybind). The theme names a plugin may rely on now include the bar's family (`surface`, `ink`, `line`, ...) and `warnFill`, the Updates badge's amber (docs/PLUGINS.md; example in examples/plugins/hello-bar).
- Idle & sleep: choose after how long the screen locks, the screen turns off and the machine sleeps, and whether it suspends or hibernates; each can be Never. Settings > General > Idle & sleep (out of the box 5, 10 and 15 minutes, as before). Keep Awake and a playing video still hold all three off. hypridle still does the waiting: the shell writes its times to `~/.config/sekaipop/idle.conf`, which the new `hypridle.conf` reads, and restarts it. Update now doesn't touch the Hyprland config, so on an existing install the section shows **Use these times**, which comments out your `hypridle.conf`'s own listeners (a copy is kept as `hypridle.conf.sekaipop-bak`) and adds the line that reads the file; running install.sh again does it too. `ipc call options set idle.lock 10`, `ipc call idle status` (issue #101; docs/IDLE.md).
- Keybinds: a bare Super tap opens Apps again only when Super was tapped on its own. Since Hyprland 0.57, every Super combination (SUPER + N, SUPER + W, ...) also opened Apps the moment Super came up. The tap is a release bind now, which Hyprland drops when another bind ran while Super was held; a tap moved to Alt or Ctrl in Settings > Hyprland > Keybinds is written the same way. Update now doesn't touch the Hyprland config, so on an existing install run install.sh again, or add `release = true, ` before `description` on the two `SUPER + SUPER_L` / `SUPER + SUPER_R` lines in `~/.config/hypr/hyprland/keybinds.lua` and `hyprctl reload`. A tap you moved in the keybinds panel is fixed by setting it again there (issue #99).
- Power rail: hovering a pill (or arrowing to it) shows what it does, beside the pill on the side away from the phone, so Sleep, Hibernate and Reboot to firmware can be told apart. On Shut down / Reboot, while something is installing or downloading, the same label turns orange and says what it would cut off; that note used to sit on the phone's side, where the phone clipped all but a sliver of it (issue #93).
- Apps: the Apps screen can list the apps you open most first. Settings > General > Launcher & lock > Apps order: A to Z (the default) or Most used, where apps you have opened lately come first and the rest follow A to Z. Use fades over a couple of weeks, so an app you stopped using drops back. With Most used on, it also decides between two equally good search matches. Counts apps opened from the Apps screen; the order moves the next time the screen opens. `ipc call options set launcher.order used` (issue #94; docs/APPS-ORDER.md).
- Keybinds: SUPER + A only opens Apps. It was also bound to Keep Awake, so opening Apps with it flipped Keep Awake every time. Keep Awake now ships without a key: give it one in Settings > Hyprland > Keybinds (Toggle Keep Awake), where Toggle power options (SUPER + Escape) is listed now too. The three test-notification keys (SUPER + ALT + F11 / F12 / =) are gone; `~/.config/hypr/hyprland/scripts/notify-test.sh image | actions | urgent` still sends them. Update now doesn't touch the Hyprland config, so on an existing install run install.sh again, or delete those lines from `~/.config/hypr/hyprland/keybinds.lua` (issue #92).
- Hyprland: window blur works again. The shipped `rules.lua` turned blur off for every window (`no_blur` on `class = ".*"`), so Settings > Hyprland > Blur and `decoration.blur.enabled` did nothing for transparent apps. The rule is gone; the shell's own surfaces are layers and stay unblurred. Update now doesn't touch the Hyprland config, so on an existing install delete that line from `~/.config/hypr/hyprland/rules.lua` (or run install.sh again) and `hyprctl reload` (issue #69).

A press still puts a tag away until you leave and come back. The tag's stuck-pointer check also knew the wrong place for a bottom or right bar's window, which could take the tag away as soon as it appeared; it now knows, and never hides a tag from a pointer that is moving over the module.
- Notifications: low-battery warnings on a laptop. A notification at 20 % and 15 % ("Battery low", plug in soon) and at 10 % and 5 % ("Battery very low" / "Battery critical", urgent, so they break through do-not-disturb and Quiet while fullscreen), once each per discharge; plugging in starts over. Settings > General > Time & alerts > Low battery warnings switches them off. Nothing runs on a desktop with no battery. FaceKey is not a type" until the shell was killed by hand (issue #79). install.sh used to say a running shell reloads its files by itself, which it doesn't once the old folder is moved aside. The reload error card has a **Restart shell** button for the same case (`scripts/system/restart-shell.sh`).

It updates the real folder, so the links keep pointing at the new files; it used to refuse with a message the button cut off. When an update doesn't apply, the reason is shown in full under the status (issue #21).
